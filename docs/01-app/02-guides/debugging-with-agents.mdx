Your coding agent can ask the running Next.js dev server for diagnostics directly. You don't need to install a skill or configure an MCP client.

## Start the app

Run your project's development script, such as `npm run dev`. If `next dev` reports that a server is already running, reuse it. Give your agent the URL printed in the terminal, the affected route, and the steps that reproduce the problem.

## Find the error

On Next.js 16 and later, `next dev` exposes an HTTP endpoint at `/_next/mcp`. Your agent sends `tools/list` there to discover what's available in your installed version. To use one of those tools, it sends `tools/call` **to the same endpoint** with the tool name and its arguments.

Start with `check_route` to check a route for problems. Pass the path and query string, for example `{"path":"/settings"}`. It compiles and requests the route without a browser. Read `compilationIssues` for compiler diagnostics and, with Cache Components enabled, `validation.errors` for what Next.js found when it validated the route.

A page can render and still show an amber **Insight** if a navigation has to wait for data. See [Issues and Insights](https://github.com/vercel/next.js/blob/ecc4775a74f65b1376e8fc571dfc885692f1fabb/docs/01-app/02-guides/devtools.mdx#issues-and-insights) for what the badge means and [Validate instant navigation](/docs/app/guides/instant-navigation#validate-instant-navigation) for which navigations Next.js checks.

- **For a browser error**, open the page, reproduce the problem, then call `get_errors` with no arguments. It reads the connected browser's error state.
- **For log output**, call `get_logs` with no arguments and read the file at the path it returns.

<details>
<summary>See the HTTP requests</summary>

Use the port your dev server printed. For example, on port 3000:

```bash filename="Terminal"
mcp() {
  curl -sS http://localhost:3000/_next/mcp \
    -H 'Content-Type: application/json' \
    -H 'Accept: application/json, text/event-stream' \
    -d "$1"
}

mcp '{"jsonrpc":"2.0","id":1,"method":"tools/list","params":{}}'
```

Choose the call that matches the problem:

```bash filename="Terminal"
mcp '{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"check_route","arguments":{"path":"/settings"}}}'
mcp '{"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"get_errors","arguments":{}}}'
mcp '{"jsonrpc":"2.0","id":4,"method":"tools/call","params":{"name":"get_logs","arguments":{}}}'
```

</details>

If your agent already has the optional [Next.js DevTools MCP connector](/docs/app/guides/mcp), it can use `nextjs_index` to discover the server and `nextjs_call` to call its tools instead.

## Verify the fix

After editing the route, call `check_route` again with the same path and query string. Check that the original diagnostic is gone. For a validation fix, look for `validation.status` of `"validated"` and an empty `validation.errors` array. If the status is `"not-run"`, read `validation.reason`; the route hasn't been validated, even if `ok` is `true`.

For a browser interaction, repeat the steps that exposed the problem and check the visible result and the console. The optional [`next-dev-loop` skill](/docs/app/guides/ai-agents#next-dev-loop) can help your agent do that.

If the issue happens while a navigation is pending, a check after the page settles will miss it. The [Instant Navigation guide](/docs/app/guides/instant-navigation#prevent-regressions-with-e2e-tests) shows how to assert what appears before the response arrives.

For a production-only issue, reproduce it with `next build` and, for runtime behavior, `next start`. If prerendering fails, [`--debug-prerender`](/docs/app/guides/building#debug-prerender-errors) gives you readable server frames; [`--debug-build-paths`](/docs/app/api-reference/cli/next#building-specific-routes) narrows a large build to selected routes. Use a normal build to verify the fix.
