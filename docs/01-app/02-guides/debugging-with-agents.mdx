title: How to run and debug a Next.js app with a coding agent
nav_title: Debugging with a coding agent

---

To debug a Next.js app with a coding agent, share the route, what you expected to happen, and what happened instead. With the app running, you and your agent can narrow down whether the problem occurs when Next.js renders the route, in the browser, or only during a production build.

## Start the app

Run your project's development script from the app directory. For example:

```bash filename="Terminal"
npm run dev
```

Open the URL printed by `next dev`. If Next.js finds a dev server already running for this project, use that one. For an issue that only happens when you're signed in, reproduce it in your signed-in browser.

## Find the error

| What you see                                             | How your agent can help                                                                                                                                                                                                                                                                                                                                                                         |
| -------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A page won't compile or render                           | With [Next.js DevTools MCP](/docs/app/guides/mcp) connected, your agent can use `nextjs_index` to discover the running server. If it lists `check_route`, the agent can call it through `nextjs_call` with the affected path, such as `/settings`, including the query string if relevant.                                                                                                      |
| A click fails or the DevTools badge shows an issue       | Repeat the click with the browser open. Your agent can read errors from the connected browser with `get_errors` and locate the development log with `get_logs`. The [DevTools guide](https://github.com/vercel/next.js/blob/ecc4775a74f65b1376e8fc571dfc885692f1fabb/docs/01-app/02-guides/devtools.mdx#issues-and-insights) explains the difference between an error and a navigation Insight. |
| A prerender error appears only during a production build | [`next build --debug-prerender`](/docs/app/guides/building#debug-prerender-errors) gives you readable server frames. In a large app, [`--debug-build-paths`](/docs/app/api-reference/cli/next#building-specific-routes) limits the build to selected routes. Don't deploy the diagnostic build.                                                                                                 |

A route check can tell you why a page failed to render. Look for a source location in `compilationIssues` or `validation.errors`. With Cache Components enabled, `validation.status: "validated"` and no errors mean that render passed. If it says `"not-run"`, read the reason. A redirect to sign-in, for example, means the requested page wasn't checked, even if the tool returned `ok: true`.

<details>
<summary>Call the dev server directly without an MCP client</summary>

Replace port 3000 with the port your server printed. List the tools before calling one; the available tools depend on the installed Next.js version.

```bash filename="Terminal"
mcp() {
  curl -sS http://localhost:3000/_next/mcp \
    -H 'Content-Type: application/json' \
    -H 'Accept: application/json, text/event-stream' \
    -d "$1"
}

mcp '{"jsonrpc":"2.0","id":1,"method":"tools/list","params":{}}'
```

If the list includes `check_route`, send the concrete page path:

```bash filename="Terminal"
mcp '{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"check_route","arguments":{"path":"/settings"}}}'
```

</details>

## Verify the fix

Repeat the steps that originally failed, using the same URL, session, and development or production mode.

- **For a render error**, check the route again and confirm that validation ran and the original error is gone.
- **For a browser issue**, repeat the interaction and check the result as well as the console. If the problem happened while a request was pending, check before the response arrives too. The [Instant Navigation guide](/docs/app/guides/instant-navigation#prevent-regressions-with-e2e-tests) shows how to test this with [Playwright's `instant()` helper](/docs/app/guides/testing/playwright#testing-instant-navigations). The optional [`next-dev-loop` skill](/docs/app/guides/ai-agents#next-dev-loop) can help your agent drive the browser and check framework diagnostics together.
- **For a production-only issue**, run a normal `next build`. If the problem occurs at runtime, use `next start` and reproduce it against that build.
