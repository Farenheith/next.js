Suppose the **Buy** button on your product page moves just as you're about to click it. Tell your coding agent where you started and what you saw: “Open the product list and click the mug. When the stock count appears, the Buy button moves down.” That gives you both a way to reproduce the problem and check the fix.

## Start the app

Run your project's development script from the app directory. For example:

```bash filename="Terminal"
npm run dev
```

Open the URL printed by `next dev`. If Next.js finds a dev server already running for this project, use that one. For an issue that only happens when you're signed in, reproduce it in your signed-in browser.

## Find the error

| What you see                                             | How your agent can help                                                                                                                                                                                                                                                                                                                                                                         |
| -------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A page won't compile or render                           | With [Next.js DevTools MCP](/docs/app/guides/mcp) connected, your agent can use `nextjs_index` to discover the running server. If it lists `check_route`, the agent can call it through `nextjs_call` with the affected path, such as `/products/mug`, including the query string if relevant.                                                                                                  |
| A click fails or the DevTools badge shows an issue       | Repeat the click with the browser open. Your agent can read errors from the connected browser with `get_errors` and locate the development log with `get_logs`. The [DevTools guide](https://github.com/vercel/next.js/blob/ecc4775a74f65b1376e8fc571dfc885692f1fabb/docs/01-app/02-guides/devtools.mdx#issues-and-insights) explains the difference between an error and a navigation Insight. |
| A prerender error appears only during a production build | [`next build --debug-prerender`](/docs/app/guides/building#debug-prerender-errors) gives you readable server frames. In a large app, [`--debug-build-paths`](/docs/app/api-reference/cli/next#building-specific-routes) limits the build to selected routes. Don't deploy the diagnostic build.                                                                                                 |

A route check can tell you why a page failed to render. Look for a source location in `compilationIssues` or `validation.errors`. With Cache Components enabled, `validation.status: "validated"` and no errors mean that render passed. If it says `"not-run"`, read the reason. A redirect to sign-in, for example, means your signed-in product page wasn't checked, even if the tool returned `ok: true`.

<details>
<summary>Call the dev server directly without an MCP client</summary>

Replace port 3000 with the port your server printed. List the tools before calling one; the available tools depend on the installed Next.js version.

```bash filename="Terminal"
mcp() {
  curl -sS http://localhost:3000/_next/mcp \
    -H 'Content-Type: application/json' \
    -H 'Accept: application/json, text/event-stream' \
    -d "$1"
}

mcp '{"jsonrpc":"2.0","id":1,"method":"tools/list","params":{}}'
```

If the list includes `check_route`, send the concrete page path:

```bash filename="Terminal"
mcp '{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"check_route","arguments":{"path":"/products/mug"}}}'
```

</details>

## Verify the fix

Go back to the product list and click the mug again. Opening the product URL directly skips the click where you saw the problem.

1. **While stock is loading:** Can you already see the product name and tell that stock is still loading? For [instant navigations](/docs/app/guides/instant-navigation#prevent-regressions-with-e2e-tests), your agent can check what's visible _before_ the response arrives with [Playwright's `instant()` helper](/docs/app/guides/testing/playwright#testing-instant-navigations).
2. **When stock arrives:** Does the count replace the placeholder without moving the Buy button? Try a narrow window too. Your agent can record the button's position at both points in a browser test.
3. **When you come back:** If your change affects caching, update the stock through the app, navigate away, and return. You should see the new value.

If you'd like your agent to drive the browser, the optional [`next-dev-loop` skill](/docs/app/guides/ai-agents#next-dev-loop) combines browser checks with the dev server's diagnostics. To confirm automatic prefetching in production, repeat the same click against a normal `next build` and `next start`.
